Plain text

Hvad er plain text?

Tekst og intet andet. Ingen skjult formatering, ingen indlejrede billeder, intet program, der skal til for at åbne den.

  • En .py-fil er plain text. En .csv er plain text. En .md er plain text.

  • En .docx er ikke. Heller ikke en .pages eller en .xlsx.

  • Plain text kan åbnes af ethvert program på enhver computer … i dag og om 30 år.

Tekst er tal

Første princip fra lektion 1. Hvert tegn er gemt som et tal:

Fjorten tegn, fjorten tal. Men æ, ø og å fylder to tal hver. Tegnsættet hedder UTF-8, og det er grunden til, at danske bogstaver kan blive til Ã¦ og Ã¸, når et program læser filen med det forkerte.

En Word-fil er ikke tekst

Opvarmningsarket fra lektion 6 er to sider i Word. Pakker man det ud, ser det sådan ud:

word/document.xml            79.664 byte    selve teksten, gemt i XML
word/styles.xml               4.409 byte    skrifttyper og formater
word/numbering.xml            3.172 byte    nummererede lister
word/_rels/document.xml.rels  1.057 byte    hvad der hænger sammen med hvad
docProps/core.xml               643 byte    forfatter, dato
[Content_Types].xml           2.104 byte    hvilke slags filer der er med
_rels/.rels                     718 byte

En .docx er en zip-fil med elleve filer. Teksten er der, men begravet i maskinlæsbar markup. Man kan ikke se, hvad der er ændret mellem to udgaver, kun at noget er.

Hvorfor plain text?

Kieran Healy, The Plain Person’s Guide to Plain Text Social Science:

  • Det holder. Formatet forældes ikke. Programmet kan forsvinde; teksten kan stadig læses.

  • Alle værktøjer kan bruge det. Python, Git, pandoc, Quarto og enhver editor.

  • Man kan se, hvad der er ændret. Linje for linje.

  • Indhold og udseende er adskilt. Man skriver hvad, og et program bestemmer hvordan det skal se ud.

Git kan se forskellen

Det er præcis det, git diff viser. Linjer med - er fjernet, linjer med + er tilføjet. Det kan kun lade sig gøre, fordi filen er tekst.

Compilere

Fra det, mennesker skriver, til det, maskiner gør

Kernighan kapitel 5: processoren i lektion 1 kan kun en håndfuld simple instruktioner: hent et tal, læg to tal sammen, gem resultatet.

  • Ingen skriver programmer i de instruktioner. Vi skriver i højniveausprog som Python.

  • En compiler oversætter fra højniveausproget til maskinens instruktioner før programmet kører.

  • En fortolker (interpreter) oversætter og udfører undervejs, linje for linje.

Python kan vise sin oversættelse

andel fra lektion 4, oversat: hent antal, hent i_alt, del dem, returnér. Det er tæt på den lille computer i lektion 1. (Detaljerne afhænger af Python-versionen.)

Hvad står der?

Python har oversat andel til fire instruktioner. Læs dem oppefra og ned:

Linje Instruktion Det betyder
3 RESUME Python gør sig klar til at køre funktionen. Den gør ikke noget, man kan se
4 LOAD_FAST_LOAD_FAST (antal, i_alt) Hent de to tal, funktionen fik med, og læg dem klar
BINARY_OP 11 (/) Tag de to tal, og del det ene med det andet
RETURN_VALUE Giv resultatet tilbage til den, der kaldte

  • Tallene til venstre er linjenumrene i cellen: def står på linje 3, return på linje 4. Én linje Python blev til tre instruktioner.

  • Tallene i midten (1 og 11) er Pythons egne koder. 11 betyder division. Dem behøver man ikke kunne.

  • Hent, regn, giv tilbage. Det er præcis, hvad den lille computer i lektion 1 kunne: hente et tal, regne med det og gemme resultatet.

Kører I cellen på en anden Python-version, ser oversættelsen lidt anderledes ud. Ældre udgaver henter de to tal med to instruktioner i stedet for én. Det gør ikke noget: grænsefladen andel(antal, i_alt) er den samme, kun implementationen under den er ændret. Det er lektion 4 igen.

Dokumenter kan også oversættes

En compiler oversætter ét sprog til et andet. Det gælder ikke kun programmer.

  • pandoc oversætter mellem dokumentformater: Markdown til HTML, Word, PDF og mange flere. Healy kalder det et af de vigtigste værktøjer i sin værktøjskasse.

  • Quarto bygger oven på pandoc og kan desuden køre kode undervejs.

  • Disse slides er skrevet i plain text og oversat til den hjemmeside, I kigger på nu.

Markup

Tekst om tekst

Markup er tegn i teksten, der fortæller noget om teksten: at noget er en overskrift, at noget skal være fed, at noget er et link.


Det, der skal stå HTML Markdown
en overskrift <h2>Opslag</h2> ## Opslag
fed <strong>fed</strong> **fed**
kursiv <em>kursiv</em> *kursiv*
et link <a href="om.html">Om</a> [Om](om.qmd)
et punkt <li>Handel</li> - Handel

HTML

Kernighan kapitel 10: en hjemmeside er en tekstfil med HTML (HyperText Markup Language). Browseren læser markuppen og bestemmer, hvordan det skal se ud.

HTML er bare tekst. Python kan skrive den med en f-streng og det er præcis, hvad Quarto gør med jeres tabeller fra brancher().

Markdown

HTML er til maskiner. Markdown er til mennesker: markup, der ser ud som almindelig tekst, også før den er oversat.

Samme tabel, halvt så mange tegn og man kan (nogenlunde) læse den, som den står. Markdown blev opfundet med netop det mål.

Markdown på én side

# Overskrift
## Underoverskrift

**fed** og *kursiv*

- et punkt
- et punkt mere

1. første
2. anden

[et link](om.qmd)

`kode i teksten`
| Branche | Kvinder |
|---|---|
| Handel | 45,4 % |

```python
print("en kodeblok")
```

> et citat

::: {.callout-note}
En boks — kun i Quarto
:::

I VS Code og Positron viser Ctrl + Shift + V (⌘ + Shift + V på Mac) en forhåndsvisning af en Markdown-fil.

YAML

Øverst i en .qmd-fil og i _quarto.yml står YAML: indstillinger skrevet som nøgle: værdi.

website:
  title: "Diversitetsbarometeret"
  navbar:
    left:
      - href: index.qmd
        text: Forside

  • Indrykningen er grammatik. To mellemrum ind betyder “hører til linjen over”. Det er samme princip som i Python.

  • Efter et kolon kommer et mellemrum. text:Forside er en fejl. text: Forside er rigtigt.

CSS

Markup siger hvad noget er. CSS siger, hvordan det skal se ud.

h2 { color: #1f5fbf; }


Det er lagene fra lektion 4 igen. Indholdet ved ikke, hvordan det ser ud; udseendet ved ikke, hvad indholdet siger. Man kan skifte det ene ud uden at røre det andet. Et tema i Quarto er bare en færdig CSS-fil.

Fra .qmd til hjemmeside

Quarto er en compiler for dokumenter


  • Python-koden kører én gang, når siden bygges. Den, der læser siden, kører ingen Python.

  • Resultatet (tabeller, figurer) står i HTML’en som om det var skrevet.

  • _site/ er resultatet, ikke kilden.

Siderne i barometeret

En hjemmeside i Quarto er en mappe:

_quarto.yml      navigationen, temaet, hvilke sider der findes

index.qmd        Forside         I skriver den
barometer.qmd    Barometer       et eksempel på figuren
opslag.qmd       Opslag          tabeller og figurer fra brancher()
om.qmd           Om              henter app/om.md


Byg og se den, mens I arbejder:

quarto preview

Den samme kode, et nyt lag

opslag.qmd laver ingen beregninger selv. Den kalder de funktioner, I læste i lektion 6:

```{python}
from app.barometer import Referencetal
from app.barometer.opslag import brancher
from app.barometer.figur import tegn_opslag

referencetal = Referencetal()
```

```{python}
figur = tegn_opslag(brancher(referencetal, "kvinder"))
```

Én tekst, to steder

om.qmd er kun tre linjer:

---
pagetitle: "Om barometeret"
---

{{< include app/om.md >}}

  • Om-siden i appen og Om-siden på hjemmesiden er den samme fil.

  • Retter man den ét sted, er den rettet begge steder.

  • Det er samme idé som opslagstabellerne i lektion 5: noget, der skal være ens, skal kun stå ét sted.

Workshop

Før I starter

Sync fork og git pull. Så får I _quarto.yml, barometer.qmd, opslag.qmd og om.qmd, og en index.qmd med kommentarer, I skal skrive om.

  • Positron har Quarto indbygget. VS Code skal have Quarto installeret fra quarto.org og udvidelsen Quarto.

  • Quarto skal kunne køre Python. Tjek det i terminalen:

    quarto check jupyter

    Mangler Jupyter, så: python -m pip install jupyter

Øvelse 1: Markdown på ti minutter

Lav en fil, kladde.md, og genskab teksten fra arket — overskrifter, fed og kursiv, en liste, et link og en tabel.

Åbn forhåndsvisningen ved siden af med Ctrl + Shift + V, og ret, til de ser ens ud.

Øvelse 2: Forsiden

Åbn index.qmd, og skriv forsiden. Kommentarerne siger, hvad der skal stå hvor.

  • Hvad barometeret kan: to eller tre sætninger, med det vigtigste ord i fed

  • Tre sider: en liste med et link til hver

  • Det, barometeret ikke gør: de vigtigste beslutninger fra KOEREPLAN.md


Kør quarto preview i terminalen. Siden opdaterer sig selv, hver gang I gemmer.

Øvelse 3: Opslag og Barometer

Koden står der allerede. Mangler der noget, er det teksten.

  • opslag.qmd: forklar, hvordan man læser figuren — hvad er søjlen, hvad er prikken? Og hvad er en median, og hvad er den ikke?

  • barometer.qmd: forklar figuren med jeres egne ord — det lyse bånd, det mørke bånd, stregen og trekanten.

Øvelse 4: Navigationen og udseendet

Åbn _quarto.yml.

  1. Byt om på rækkefølgen af to sider i menuen. Gem, og se det skifte.

  2. Skift temaet fra cosmo til et af Quartos andre: fx flatly, litera eller minty.

  3. Ret teksten i bunden af siden, så den nævner jeres gruppe.

  4. Lav en fejl med vilje: fjern mellemrummet efter et kolon. Hvad siger Quarto? Ret den igen.
